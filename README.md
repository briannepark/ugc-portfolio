# ugc-portfolio

Brianne's UGC / brand-partnership portfolio site. Deploys automatically to
Windmill (as a "Raw App") on every push to `main`.

## How it's structured

```
site/                       ← source of truth: the actual HTML/CSS/JS design
  index.html
  gallery.html
scripts/
  build-app.mjs              ← turns /site/*.html into embedded JS strings
.raw_app/
  App.tsx                    ← thin React wrapper: renders the right page in an <iframe>
  index.tsx                  ← React entry point
  package.json
  pages.generated.ts         ← generated by build-app.mjs, not committed
raw_app.yaml                 ← Windmill Raw App config (name, path, public/private)
wmill.yaml                   ← scopes `wmill sync push` to just this app
.github/workflows/deploy.yml ← CI: builds + deploys on push to main
```

The site itself stays plain HTML/CSS/JS — nothing was rewritten into React. The
`.raw_app` code is just a small wrapper that loads whichever page's HTML into an
`<iframe>`, so the design stays pixel-exact. A small bridge script (appended to
the bottom of both `site/*.html` files) intercepts clicks on internal links
(`index.html`, `gallery.html`, and in-page anchors like `#about`) and asks the
wrapper to switch pages, so navigation and "Gallery"/"(More)" links keep working.

## To edit the site

Just edit `site/index.html` or `site/gallery.html` directly and push to `main`
— everything else regenerates automatically in CI.

## One-time setup (before the first deploy works)

1. **Create the Windmill app once.** ✅ Done — `raw_app.yaml` points at
   `u/brianne/ugc_portfolio`.

   One thing still worth double-checking: the **local file layout Windmill's
   CLI expects**. Run `wmill sync pull`
   from an empty version of that app once, locally, and compare what it writes
   against this repo's `raw_app.yaml` / `.raw_app/` layout. Windmill's docs weren't
   fully consistent on whether these live at the repo root or nested under a path
   mirroring `f/...` in the workspace, so this is worth a quick sanity check
   before the first CI run — if `wmill sync pull` writes them somewhere else,
   move this repo's `raw_app.yaml`/`.raw_app/` contents to match, and I can help
   reconcile from there.

2. **Create a Windmill API token** (Windmill → user settings → tokens) with at
   least `apps:write` scope.

3. **Add three GitHub repo secrets** (repo → Settings → Secrets and variables →
   Actions):
   - `WM_BASE_URL` — e.g. `https://app.windmill.dev`
   - `WM_WORKSPACE` — your Windmill workspace id
   - `WM_TOKEN` — the token from step 2 (never share this in chat/PRs — GitHub
     secrets are the right place for it)

4. Push to `main` (or run the "Deploy to Windmill" workflow manually from the
   Actions tab) and check the Actions log for the deploy URL.
